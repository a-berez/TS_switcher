# Регрессионные проверки

Проверки версии 1.1.1 ожидают корректное поведение. Любое нарушенное ожидание завершает тест с ненулевым кодом. Исходники и пользовательские профили при проверках не меняются.

## Логика и сборка

Из корня проекта:

```text
python tools/generate-themes.py --check
node tests/audit-themes.cjs
node tests/audit-ui.cjs
node tests/audit-background.cjs
python tests/audit-build.py
```

`audit-ui` — 1561 ожидание: таблицы URL одиннадцати хостов, оба маршрута турниров ТС (tournament/tournaments), hash/query, видимость, независимые контексты runtime/storage, параллельные записи, быстрые изменения формы, ошибки сохранения. Проверяется A2: канонический слеш, точные карточки, списки и релизы только внутри зеркал A2, миграция видимости без сброса настроек и разрешения обоих manifest. DOM и WebExtension API здесь заменены моделями.

`audit-background` — 23 сценария модели: auth/bypass, порядок настроек и навигаций, fallback, logout/закрытие, восстановление состояния, серверный info/login, независимый preferred A2 и ограничение TS grace после восстановления старых правил. RE2 модель не эмулирует: настоящая установка правил проверяется Chromium.

`audit-build` запускает настоящую сборку в уникальной временной копии, проверяет ZIP, файлы, версии, отсутствие изменения src/старых ZIP и отказ при повреждённых ресурсах. Проверяет извлечение описаний всех версий из `CHANGELOG.md`, общее описание для beta-сборок и отсутствие описания для неизвестной версии в обоих workflows. Выполняет ветви changelog и проверки тегов с подменой git-команд, без сети и публикации. Дополнительно исполняет подготовку AMO в чистой папке, проверяет возможность сохранить XPI и расположение GitHub Release перед магазинными шагами. Нужен Python 3.9+ и Bash (на Windows используется Git for Windows). Эти проверки включены в релизные workflows.

`audit-themes` — 64 ожидания политики тем, приоритетов ручного выбора, независимости сайтов, смены вкладок, запоздалых сообщений и освобождения observer. Генератор с `--check` проверяет совпадение палитр с themes.css. При изменении исходной палитры выполнить `python tools/generate-themes.py`.

## Настоящие браузеры

Проверенное окружение: Node 24.19, Playwright 1.63.0, Chromium 153.0.8010.12, Firefox 155.0. Нужен установленный Playwright с полным Chromium и Firefox; headless shell расширения не поддерживает. Браузерные тесты пока запускаются локально отдельно от лёгких CI-проверок.

Если Playwright установлен глобально, PowerShell:

```powershell
$env:PLAYWRIGHT_MODULE = Join-Path (npm root -g) 'playwright'
node tests/audit-browser.cjs
node tests/audit-theme-browser.cjs
node tests/audit-worker.cjs
node tests/audit-firefox.cjs
```

Можно явно задать `CHROMIUM_PATH` и `FIREFOX_PATH` к тестовым браузерам. Без этих переменных используются браузеры установленного Playwright. Для Firefox нужен OpenSSL; на Windows используется `C:/Program Files/Git/usr/bin/openssl.exe`, путь можно переопределить через `OPENSSL_PATH`.

- `audit-browser`: 53 ожидания в настоящем Chromium. DNR, tabs, storage и DOM настоящие; HTTPS-ответы заменены Playwright на успешные страницы, HTTP 302, DNS-ошибку и отмену запроса. Проверяются ТС → A2 → ТС, переходы с релиза между зеркалами A2, отдельный preferred A2 с bypass, семь колонок копирования без переполнения, реальные переходы, bypass, одиннадцать хостов, fallback, вход/выход, сообщения и параллельные записи.
- `audit-theme-browser`: 288 проверок Chromium: 16 сочетаний тем ТС и две палитры рейтингов, сравнение реальных CSS-переменных с исходным CSS для попапа и options, независимая палитра кнопок копирования ТС на рейтингах, независимые настройки, фактический контраст текста ТС, CSS повышенного контраста, gg с отличающимся режимом страницы и попапа, смена вкладки и DOM кнопок. Также проверяет оформление options, ручные и внешние изменения, получение темы сайта и резерв после закрытия вкладок. Оба браузерных набора проверяют загрузку локального Noto Sans; сборка проверяет наличие файла шрифта и OFL-лицензии. Проверяет изменения data-contrast сайта, приоритет ручного выбора и все 16 вариантов палитры копирования ТС на рейтингах. Создаёт `audit-themes.out.png` и `audit-themes-options.out.png`.
- `audit-worker`: три проверки настоящего stop/start service worker через CDP: возврат на последнее зеркало, сохранение grace, возобновление preferred после logout.
- `audit-firefox`: 47 ожиданий в настоящем Firefox. Дополнение временно устанавливается через локальный Mozilla RDP. Локальный HTTPS-сервер, временный сертификат и DNS-настройка только тестового профиля обеспечивают контролируемые ответы даже после webRequest redirect. Проверяются manifest, настройки/runtime, независимый перехват ТС/A2, bypass, auth, fallback.

Все профили временные и удаляются. Учётные записи сайтов не используются. `audit-*.out.json` и снимки `audit-*.out.png` — пересоздаваемые локальные результаты, исключённые из Git. Exit 1 означает нарушенное ожидание; интеграционные browser/firefox скрипты используют exit 2 для незавершённого запуска/сбоя стенда.

## Граница проверки

Попап Chromium загружается страницей расширения при активной исходной вкладке. Нативное окно панели инструментов и системный clipboard не проверяются этими сценариями. Настоящая авторизация, актуальность маршрутов внешних сайтов, минимальные версии браузеров и публикация в магазины требуют отдельной проверки. HTTP-ответы 4xx/5xx с телом и зависшая загрузка не входят в механизм fallback по сетевым ошибкам.
