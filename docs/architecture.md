# Architecture

Расширение работает на одиннадцати хостах: четыре TS и семь хостов рейтингов, включая три зеркала A2.

## Границы

Внутри: попап, options, `sites.js`, `settings.js`, отдельные background Chromium/Firefox, сборка ZIP. Снаружи: `rating.chgk.info`, `rating.pecheny.me|kz|ru`, `rating.chgk.gg`, `rating.chgk.fun`, `chgk.quest`, `elo-chgk.uk`, `a2.pecheny.me|kz|ru`. Синхронизации авторизации и произвольных доменов нет.

## URL и интерфейс

Попап читает URL активной вкладки целиком, включая query и fragment. `Sites.hasExactPath` разрешает главную, игрока, команду, турнир и любой путь внутри зеркал TS→TS или A2→A2. На ТС распознаются оба маршрута турниров: `/tournament/:id` и `/tournaments/:id`, включая завершающий слеш и подпути. Между зеркалами сохраняется весь исходный путь, в том числе вариант маршрута; для рейтингов тип нормализуется в tournament. Неподдерживаемые межсайтовые переходы скрыты. TS-цели сохраняют подпуть/query/hash, рейтинги получают канонический путь сущности; копия текущего хоста сохраняет исходный путь.

Клик TS или A2 добавляет `ts_switcher_direct=1` и не меняет preferred. Content script удаляет параметр, сохраняя `history.state`. Попап обновляется по событиям tabs/storage; видимость учитывается в ключах обычных кнопок и fallback. Интерфейс использует локально упакованный Noto Sans, внешних запросов UI нет. Кнопки копирования ссылок на ТС используют обводку --border-strong из своей палитры: в светлой Classic это тёмный песочный #a0936b, а не цвет текста. При наведении цвет обводки сохраняется; клавиатурный фокус остаётся видимым. На рейтингах эти кнопки сохраняют собственную палитру ТС, включая наведение: семейство, режим и ручная контрастность берутся из настроек ТС. При auto вне ТС используется Classic и системный режим, поскольку страница рейтинга не сообщает настройки ТС. Локальные --copy-ts-* генерируются из тех же токенов themes.css; палитра остального рейтингового интерфейса не меняется.

A2 использует ID ТС: `/players/:id/`, `/teams/:id/`, `/tournaments/:id/`. Входящие адреса принимаются также без завершающего слеша и с подпутями, по общему правилу рейтингов. В интерфейсе используется общая подпись «Рейтинг (a2.pecheny.me)», короткие кнопки — «a2.me», «a2.kz», «a2.ru». В секции переключения рейтингов A2 занимает один ряд равных по ширине кнопок; скрытые и текущий хост исключаются, оставшиеся делят ширину ряда. Полный целевой URL доступен в title. Списки и архивные релизы A2 не имеют соответствия на других рейтингах и ТС, но доступны между зеркалами A2 с сохранением полного пути, query и hash. Проверенные источники и ограничения — [a2-mapping.md](a2-mapping.md). Кнопки копирования образуют два ряда: до четырёх ТС и семи рейтингов; уменьшенные горизонтальные отступы рейтинговых кнопок сохраняют подписи при ширине 320 px. Новый хост включается в старые настройки видимости через mergeDefaults без сброса остальных значений.

## Настройки и состояние

`Settings.initializeBackground()` делает background единственным писателем общих объектов. Из UI частичные изменения приходят runtime-сообщениями и выполняются последовательно. Очередь продолжает работу после ошибки записи. Options сохраняет только изменённое поле, слушает storage и не перерисовывает незавершённые изменения пользователя.

Настройки — `storage.local`. Fallback и последний TS-хост Chromium — `storage.session`, при отсутствии session используется local. Старые табовые ключи удаляются при закрытии/восстановлении Chromium; срок fallback проверяется при чтении, закрытие и успешная навигация также удаляют запись.

## Перехват и авторизация

Chromium MV3 применяет DNR: общий redirect всех TS-путей, более приоритетный allow для `/login` и `/logout`, точный allow для bypass query. Правила обновляются последовательно; cachedPreferred меняется после установки правил. Исключение login grace — session allow по tabId, ограниченный requestDomains четырёх ТС (включая восстановление старых правил); при пробуждении worker оно сохраняется, последний TS-хост восстанавливается из хранилища.

Firefox MV2 использует постоянный background и блокирующий `webRequest`. Запрос ждёт начальной загрузки состояния и текущей очереди настроек. Это исключает потерю grace при выгрузке event page; иконка Firefox остаётся неизменной.

Info login bounce: при preferred `/login` основного сайта переписывается на preferred; при off — на последнее зеркало вкладки. Chromium проверяет и начало перехода, и commit после HTTP redirect; перед поздним `tabs.update` проверяет актуальность вкладки. Firefox видит запрос login через webRequest. Прямая ссылка с bypass исключена.

После открытия `/login` вкладка освобождена от preferred до запроса `/logout` или закрытия. Logout обрабатывается до commit, поэтому HTTP redirect на главную не оставляет grace. При полном новом запуске браузера открытый `/login` восстанавливает grace; для обычных страниц обещания сохранять исключение между браузерными сессиями нет.

Предпочитаемый A2 задаётся отдельно в options через `preferredA2Host`: off (по умолчанию), a2.pecheny.me, a2.pecheny.kz или a2.pecheny.ru. Скрытый для переключения хост нельзя выбрать; скрытие выбранного выключает перехват. Запись идёт через общую очередь Settings. Chromium устанавливает отдельную группу DNR redirect-правил, Firefox обрабатывает A2 до логики ТС. Перехват действует на верхний документ и сохраняет весь путь, query/hash; bypass общий с ТС. A2 не участвует в TS login grace, auth bounce и fallback. Новые зеркала добавлены по сообщению владельца от 2026-10-10; работа их серверов до запуска не подтверждена.

## Fallback

При preferred=off и сетевой ошибке TS сохраняется URL для предложения зеркала. Отмена навигации исключена. Ошибка привязана к поколению навигации: запоздавший обработчик не должен вернуть запись после успеха/закрытия. Очистка идёт по `webNavigation.onCompleted`; `tabs.onUpdated complete` не подходит, поскольку приходит и на браузерных страницах ошибки. HTTP-ошибка с телом ответа и бесконечная загрузка не запускают fallback.

## Сборка и проверка

`python build.py` проверяет оба комплекта ресурсов и версии, затем создаёт versioned ZIP и latest-копии. Firefox использует свой manifest и background под именами `manifest.json`/`background.js`. Исходники и старые versioned ZIP не меняются. Оба manifest и версия сборки используют `1.1.1`. Состояние публикации — `status.md`. Статус магазинов — `status.md`. По решению владельца от 2026-10-04 локальная beta.8 (`1.0.0.8`) не определяет номер публичного выпуска: она тестировалась только у него. Сборщик по-прежнему отвергает понижение относительно текущих исходных manifest.

Описания выпусков в обоих workflows берутся из `CHANGELOG.md`, из раздела соответствующей версии. В `README.md` остаётся краткое описание последнего релиза, в `CHANGELOG.md` — пользовательская история всех релизов, в `full_changelog.md` — все релизы с техническими подробностями. Во всех трёх документах 1.0.0 описывается одним разделом относительно последнего стабильного релиза 0.3.5, без разделения на beta и без перечня ошибок, появившихся только внутри beta. Для описаний beta-выпусков CI убирает суффикс `-beta.N` и берёт общий раздел версии; номера сборок и манифестов от этого не меняются.

CI запускает проверки логики и изолированной сборки до выпуска. В tag-from-commit GitHub Release создаётся перед магазинными шагами: отказ магазина не должен пропускать GitHub-выпуск. Перед подписью AMO создаётся каталог web-ext-artifacts для скачивания XPI. Тесты настоящих браузеров — `tests/README.md`; они работают с отдельными профилями и контролируемыми ответами сайтов. Обоснование владения состоянием — `decisions/2026-10-01-background-state.md`.

## Темы попапа

На 2026-10-04 попап поддерживает Classic, Oldschool, Catppuccin и Colorblind в light/dark с обычной и повышенной контрастностью (16 сочетаний) и две палитры gg для всех рейтингов. Цвета ТС генерируются `tools/generate-themes.py` из корневого `themes.css` в `src/popup-themes.css`; генерируемый файл хранится в src и проверяется в CI. Компоненты — `src/popup.css` и `src/options.css`; палитры рейтингов и усиление границ при повышенной контрастности — `src/theme-overrides.css`. Источники рейтинга с фиксированным коммитом и обоснование привязки цветов — `popup-themes-plan.md`.

`theme.js` содержит политику выбора; `popup-theme.js` управляет соединением с верхним документом активной вкладки, отдельно от рендера кнопок. `content.js` читает на ТС атрибуты html data-site-theme, data-bs-theme, data-theme-pref и data-contrast; на gg — matchMedia(prefers-color-scheme), как в исследованном rating-ui. MutationObserver и media change работают только пока открыто соединение с попапом или options. Изменения темы не пересоздают кнопки и не записываются в storage. Новых разрешений нет.

Четыре независимые настройки в Settings (значение по умолчанию auto):

- tsColorScheme: auto/light/dark. Auto следует фактическому режиму ТС; резерв — предпочтение light/dark сайта, затем система.
- tsTheme: auto/classic/oldschool/catppuccin/colorblind. Auto следует семейству ТС; резерв — classic.
- tsContrast: auto/normal/more. Auto следует data-contrast="high" самого ТС (внутреннее значение more); отсутствие или неизвестное значение означает normal. Предпочтение контрастности ОС не участвует. More выбирает контрастную палитру соответствующего семейства и режима из CSS сайта, normal принудительно выключает её.
- ratingColorScheme: auto/light/dark. Auto на gg берётся из вкладки; на .fun, chgk.quest, elo-chgk.uk, a2.pecheny.me — из media query попапа.

Ручные параметры имеют приоритет над страницей и резервом; каждый параметр разрешается отдельно. Сохранение использует прежнюю очередь background, неизвестные значения нормализуются в auto, старые настройки дополняются без сброса. Тему самого сайта расширение не меняет.

Страница options использует те же палитры и настройки. `options-theme.js` выбирает активную поддерживаемую вкладку своего окна; пока активна сама страница настроек, сохраняет выбранный источник. При первом открытии без активного поддерживаемого сайта выбирается недавно использованная поддерживаемая вкладка (lastAccessed). При отсутствии таких вкладок действуют параметры ТС с обычным резервом Classic/system. Изменения Settings, атрибутов источника, закрытие/навигация вкладки и перенос options в другое окно обновляют оформление по событиям. Соединение и наблюдатели освобождаются при закрытии страницы.

При смене вкладки/навигации старое соединение закрывается и страничное состояние сбрасывается. Поколение соединения защищает от поздних сообщений. Недоступный content script оставляет резервную палитру, не блокируя URL-кнопки или fallback; повторное подключение идёт по событиям, без polling. Начальный фон соответствует системному light/dark; точная тема и ручные настройки применяются после асинхронного чтения, поэтому возможна краткая смена цвета при открытии.

Colorblind доступен в реестре, настройках и автоматическом распознавании. Его нейтральные поверхности совпадают с Classic, цвета success/danger заменены на синие/оранжевые. Контрастность не меняет семейство. Системный forced-colors остаётся нативным механизмом доступности браузера и не используется как значение автоматической настройки ТС.
