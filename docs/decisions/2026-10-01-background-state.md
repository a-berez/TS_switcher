# Background владеет записью настроек и состоянием авторизации
Date: 2026-10-01
Status: accepted

Context: несколько страниц расширения выполняли read-modify-write одного объекта и теряли изменения. Firefox event page хранил login grace только в памяти и терял его при выгрузке.

Decision: все изменения настроек и fallback сериализованы одним background через runtime messages. UI передаёт только изменённые поля; события storage обновляют открытые формы после завершения их собственных записей. Firefox MV2 использует persistent background и ожидает загрузки настроек перед решением webRequest. Chromium сохраняет последнее зеркало в session storage и восстанавливает его вместе с session DNR rules при пробуждении worker.

Consequences: межконтекстные записи больше не конкурируют; Firefox держит небольшой background в памяти. При недоступном background сохранение завершается явной ошибкой, а не локальной несогласованной записью. Для старых Chromium без session API табовое состояние использует local и очищается по живым вкладкам.

Rejected: отдельные очереди каждой UI-страницы не устраняют межконтекстную гонку. Полная перезапись формы сохраняет устаревшие поля. Сохранение Firefox event-page состояния через sessions потребовало бы дополнительного разрешения и более сложного восстановления, поэтому для существующего MV2 выбран постоянный фон.
