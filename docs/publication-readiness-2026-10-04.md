## Пакеты стабильной версии

Первичный аудит обнаружил устаревшие локальные ZIP beta.8. По последующему указанию владельца подготовлены стабильные архивы `1.0.0`; версии обоих manifest также `1.0.0`. Из обеих лицензий удалён раздел об иконках, прочие уведомления сохранены. Лицензии в корне, src и пакетах совпадают.

| --- | ---: | --- |
| TS_switcher-1.0.0-chromium.zip | 1309797 | `1691c7097797e33407f7eab950f48197983aa62d7e249a99021579aa80adcb9a` |

Архивы без версии побайтово совпадают с соответствующими архивами 1.0.0. Хеши относятся к локальной сборке: повторная сборка в GitHub Actions меняет время ZIP-записей и может отличаться побайтово при одинаковом содержимом.

## Решения владельца

- Распространение графики разрешено; раздел об иконках удалён из лицензий по прямому указанию. Новое юридическое заключение в рамках задачи не составлялось.
- Пользователь сообщил: «Кажется, работает». Независимую проверку всех ручных сценариев это не заменяет; пользователь поручил выпуск с этим уровнем подтверждения.
- Публикуется полноценный GitHub Release `1.0.0`, не beta. Настройка beta-публикации для этой задачи не требуется.
- Техническая версия должна быть ровно `1.0.0`: beta.8 с номером `1.0.0.8` использовалась только локально у владельца. Автоматическое обновление с неё не требуется; для локального перехода нужна переустановка.

## Публикация и восстановление

Merge-коммит `6d6124c` запустил [автоматизацию 37213290490](https://github.com/a-berez/TS_switcher/actions/runs/37213290490). Проверки, сборка и создание тега прошли. Затем:

- AMO принял версию, но runner не смог сохранить `web-ext-artifacts/ts_switcher-1.0.0.xpi`: `ENOENT`. API AMO подтвердил current_version 1.0.0 и status public: [страница Firefox](https://addons.mozilla.org/en-US/firefox/addon/ts_switcher/). Это ошибка скачивания результата, не отказ магазина.
- Chrome Web Store сообщил: `FATAL: authentication failed. At least 1 of arguments: client_id, client_secret, refresh_token; is invalid.` Какое конкретно значение отвергнуто, журнал не раскрывает. Предупреждения Node.js о deprecated API не являются указанной причиной отказа.
- GitHub Release был пропущен после ошибки Chrome. Выпуск восстановлен отдельно: [1.0.0](https://github.com/a-berez/TS_switcher/releases/tag/v1.0.0), четыре ZIP из исходников неизменённого тега, без повторной отправки в AMO.

SHA-256 опубликованных архивов: Chromium `ff87e36465c88cde744561c38eab0c3a74111340e6df3c958ba76add97717329`, Firefox `489668be8f85eaa01c587b60064b20547d0d1137d8ad194d0aaf5fe55d5dc1d4`. Именованные и latest-копии совпадают; API GitHub подтвердил digest каждого вложения, draft=false, prerelease=false. Отличие от первоначальных локальных ZIP ожидаемо: сборка восстановлена из git-архива тега и имеет новое время ZIP-записей.

Workflow теперь создаёт каталог для XPI и публикует GitHub Release перед магазинами. Регрессионная проверка на чистой временной папке воспроизвела отсутствие каталога до исправления и проходит после него; весь audit-build пройден. Подписывание через AMO повторно не запускалось.

Остаётся восстановить CWS-авторизацию и отдельно отправить Chromium. Не следует повторять целиком старый запуск: AMO уже опубликовал 1.0.0, а старый SHA содержит прежний workflow. Минимальные версии браузеров, системный clipboard и живые пользовательские сессии независимо не проверялись. Передача — [handoff.md](handoff.md).
