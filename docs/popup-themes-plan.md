## Поведение и настройки

Пользователь уточнил область 2026-10-02: использовать палитру gg на всех четырёх рейтингах и добавить три независимых переключателя. Предлагаемые значения:

| Настройка | Значения | По умолчанию |
|---|---|---|
| ТС: светлая/тёмная | Автоматически / Светлая / Тёмная | Автоматически |
| ТС: тема | Как на сайте / Classic / Oldschool / Catppuccin | Как на сайте |
| Сайты рейтингов: светлая/тёмная | Автоматически / Светлая / Тёмная | Автоматически |

1. На четырёх ТС семейство и режим разрешаются независимо. Ручной выбор каждого параметра выше значения страницы. Например, принудительный Catppuccin + автоматический режим берёт light/dark с сайта; тема «Как на сайте» + принудительный dark сохраняет семейство сайта в тёмном варианте.
2. В автоматическом режиме ТС источник — data-bs-theme. При его отсутствии использовать корректное light/dark из data-theme-pref, иначе системный режим. Неизвестное/отсутствующее семейство заменять classic. Preferred TS не влияет на оформление, темы вкладок независимы.
3. Все рейтинги используют палитру gg. На rating.chgk.gg автоматический режим определяется в самой вкладке сайта; на rating.chgk.fun, chgk.quest и elo-chgk.uk — через prefers-color-scheme в попапе. Принудительный режим рейтингов выше обоих источников.
4. Если content script недоступен или страница ещё грузится, ручные настройки сохраняют силу. Автоматические значения получают резерв: classic для семейства ТС и системный режим для ТС/gg. Недоступность темы не мешает кнопкам и fallback.
5. На посторонних страницах сохраняется текущее состояние недоступности. При переходе между группами очищать старую палитру/подписку, в том числе между вкладками с одинаковым URL. Параметры ТС не влияют на рейтинги и наоборот.
6. Переключатели расположить в options в разделе «Оформление попапа». Они управляют попапом; оформление самой страницы options и запоминание темы последней вкладки не входят в этот план.

## Что найдено в rating-ui

Исследован main на коммите `7ba7b05cd2df5c19278f23603476964e426fbb50` (снимок исследования от 2026-10-02). Это проверка исходников; соответствие текущему развёртыванию gg ещё нужно проверить в браузере.

- [tailwind.config.js](https://github.com/chgk-gg/rating-ui/blob/7ba7b05cd2df5c19278f23603476964e426fbb50/tailwind.config.js): darkMode: 'media', собственных переопределений палитры нет.
- [application.tailwind.css](https://github.com/chgk-gg/rating-ui/blob/7ba7b05cd2df5c19278f23603476964e426fbb50/app/assets/stylesheets/application.tailwind.css): тёмный body, таблицы, заголовки, кнопки, поля и их состояния.
- [application.html.erb](https://github.com/chgk-gg/rating-ui/blob/7ba7b05cd2df5c19278f23603476964e426fbb50/app/views/layouts/application.html.erb): у html нет атрибута выбранной темы; layout не содержит переключателя темы.
- [bun.lock](https://github.com/chgk-gg/rating-ui/blob/7ba7b05cd2df5c19278f23603476964e426fbb50/bun.lock) фиксирует Tailwind 3.4.14; HEX сверены с [его палитрой](https://github.com/tailwindlabs/tailwindcss/blob/v3.4.14/src/public/colors.js).

В текущих исходниках gg тема определяется медиазапросом, а не атрибутами ТС. Поэтому адаптер gg должен читать matchMedia('(prefers-color-scheme: dark)') в контексте вкладки и слушать change. Это соответствует механизму сайта; угадывать тему по яркости фона или искать несуществующий data-bs-theme не нужно. Сторонние расширения, перекрашивающие страницу, не относятся к собственным темам gg.

| Назначение в исходном CSS gg | Светлая | Тёмная |
|---|---|---|
| Поверхность таблицы → основа попапа | white #ffffff | gray-900 #111827 |
| Основной текст | Для попапа предлагаем #000000; светлый body в этом CSS явно не задан | slate-100 #f1f5f9 |
| Шапка таблицы → шапка попапа | blue-100 #dbeafe | gray-600 #4b5563 |
| Фон кнопки | gray-200 #e5e7eb | gray-800 #1f2937 |
| Фон кнопки при наведении | gray-300 #d1d5db | gray-700 #374151 |
| Граница кнопки/поля | gray-300 #d1d5db | gray-600 #4b5563 |
| Наведение на строку → вторичная поверхность | gray-100 #f3f4f6 | gray-800 #1f2937 |

Перенести эти значения в локальные семантические переменные для рейтингов. Отображение уведомлений, фокус и цветовое различие групп кнопок — адаптация расширения, проверяемая отдельно на контраст; не выдавать их за готовую тему из rating-ui. Светлый фон поля и недостающие семантические значения задать явно. Tailwind и Inter в расширение не подключать. При переносе фрагментов исходного CSS сохранить уведомление MIT из LICENSE.txt проекта (Copyright 2023 MAII).

## Шаг 1. Подготовить локальные палитры

Сформировать `src/popup-themes.css` из нужных семантических переменных исходного `themes.css`. Предпочтителен небольшой Python-генератор с явным списком переменных и включением зависимостей var(...): источник палитр остаётся один, обновление воспроизводимо. Сгенерированный файл хранить в src, чтобы загрузка распакованного расширения работала без предварительной сборки.

Добавить две локальные палитры рейтингов из зафиксированных выше значений: всего восемь сочетаний. Сохранить все шесть палитр ТС и порядок их CSS-селекторов. Ограничить действие маркером темы ТС на html попапа: общий :root из исходника иначе затронет рейтинги. Подключить файл перед `popup.css`; добавить в COMMON_FILES сборщика. Сеть для загрузки темы не нужна.

## Шаг 2. Привязать элементы к переменным

Сохранить ширину 320 px, структуру разделов, шрифт Noto Sans из темы и два ряда копирования. Использовать общие семантические роли с независимыми областями палитр ТС и рейтингов. Старые фиксированные цвета body.rating-site заменить переменными новой палитры gg, чтобы они не перекрывали тёмный режим.

| Элемент | Переменные из themes.css |
|---|---|
| Фон окна и контейнера | --bg-page, --text |
| Шапка | --bg-strong, --text-strong |
| Статус и нижняя область | --bg-surface, --text, --border |
| Заголовки и вторичные подписи | --text-muted; ссылки — --link/--link-hover |
| Кнопки перехода ТС | --bg-elevated, --text, --border-input |
| Наведение на кнопки | --bg-surface-alt, --accent-border |
| Кнопки рейтингов внутри попапа ТС | --info-bg, --info-text, --info-border |
| Кнопки копирования ТС | --bg-strong, --text-strong |
| Выбор preferred TS | --bg-input, --text, --border-input |
| Fallback-баннер | --warning-bg, --warning-text, --warning-border |
| Подтверждение копирования | --success-bg, --success-text, --success-border |
| Клавиатурный фокус | --focus-ring / --shadow-focus |

Явно задавать color-scheme, цвет текста select и наследование цвета кнопкой настроек. Проверить hover, active, focus-visible и disabled. Не применять фильтр инверсии ко всему попапу: он исказит emoji и цветные индикаторы хостов. Цвета хостов из HOST_META остаются идентификаторами сайтов; проверить их различимость на шести фонах.

Палитры требуют проверки сочетаний: например, тёмный Catppuccin имеет светлый --accent. Нельзя механически оставлять белый текст поверх любого accent. Таблица использует преимущественно нейтральные поверхности и готовые пары фона/текста; финальные сочетания проверить на контраст.

## Шаг 3. Получать тему через content script

Расширить `src/content.js`, сохранив снятие bypass-маркера. Чтение темы выполнять только в верхнем документе четырёх ТС и rating.chgk.gg; на остальных рейтингах режим определяется самим попапом. Для сообщения запроса возвращать небольшой нормализованный объект семейства, фактического режима и предпочтения; не читать cookies, содержимое страницы или аккаунт.

Предпочтительный транспорт — соединение попапа с content script через tabs.connect с отдельным именем. Content script сразу отправляет текущую тему, затем наблюдает только атрибуты data-site-theme, data-bs-theme и data-theme-pref через MutationObserver. Объединять изменения и отправлять сообщение только при изменении нормализованного значения. Если режим определяется системой, слушать matchMedia change.

На gg вместо MutationObserver нужен только matchMedia change. Наблюдение нужно только пока открыт попап: при отключении последнего соединения снять observer и системный слушатель. При закрытии попапа соединение освобождается. Передавать лишь разрешённые значения перечислений; палитры находятся в расширении. Автоматически полученные данные сайта не сохранять в хранилище. Три пользовательские настройки сохранять через существующую очередь Settings/background (см. отдельный шаг ниже). Новых разрешений проектируемый способ не требует; проверить транспорт в обоих браузерах.

## Шаг 4. Применять тему независимо от кнопок

В `popup.js` добавить отдельное управление темой с ключом активной вкладки и поколением подключения. При открытии/смене вкладки сразу установить резервное оформление, затем подключиться к её content script. На loading сбрасывать данные прежнего документа; на complete повторить попытку подключения при необходимости. Ошибки подключения обрабатывать спокойно, без бесконечных повторов и polling.

Ответы старого соединения после смены вкладки или навигации игнорировать. Подписаться на изменения до получения первоначального состояния, чтобы не потерять смену темы. Менять атрибуты html без пересоздания кнопок, сброса фокуса и уведомления о копировании. Не включать тему в ключи рендера switch/copy/fallback.

При принудительном режиме расширения входящие обновления не переопределяют выбор пользователя; при автоматическом режиме и явном режиме ТС системные изменения игнорировать. При резервном системном режиме обновляться событием matchMedia. Начальный фон определить до первого отображения по системному режиму; точная тема сайта придёт асинхронно. Не обещать полное отсутствие смены цвета при открытии без дополнительного кэша; не блокировать интерфейс ожиданием темы.

## Шаг 5. Добавить три настройки

В `settings.js` добавить tsColorScheme: auto/light/dark, tsTheme: auto/classic/oldschool/catppuccin, ratingColorScheme: auto/light/dark. Значение по умолчанию для всех — auto. Нормализовать неизвестные значения в auto; старые сохранённые объекты дополнять значениями по умолчанию без сброса существующих настроек.

В `options.html` и `options.js` добавить три подписанных select. Сохранять только изменённое поле через Settings.save, используя существующую очередь background. Обновление других полей из другого окна не должно отменять несохранённый выбор пользователя. При ошибке сохранения показывать существующий статус ошибки. Архитектуру владения записью не менять.

Попап уже слушает изменения Settings в storage: на обновлении пересчитывать семейство и режим отдельно от рендера кнопок, даже если URL не менялся. Применять приоритет «ручной выбор → источник активного сайта → резерв» отдельно к каждому параметру. Настройки расширения не меняют тему самого сайта.

## Шаг 6. Проверить и документировать

- Проверки логики: три семейства ТС × два режима и два режима рейтингов, system, отсутствие/ошибки атрибутов, неподдерживаемый хост, отсутствие content script, смена темы без изменения URL.
- Проверки жизненного цикла: две вкладки с одинаковым URL и разными темами, быстрые переключения, запоздалые сообщения, навигация/перезагрузка, закрытие попапа, повторное открытие, переход на рейтинг или страницу ошибки. Повтор темы не пересоздаёт DOM кнопок.
- Настройки: все три переключателя, независимость семейства/режима ТС, независимость ТС/рейтингов, приоритет ручного выбора, миграция старых настроек, неизвестные значения, одновременные изменения из двух окон и ошибка записи.
- Рейтинги: gg получает режим от вкладки, остальные три — от окружения попапа; смоделировать разные режимы вкладки gg и попапа, смену системы, отсутствие content script и переходы между группами.
- Настоящие Chromium и Firefox: восемь сочетаний на контролируемых страницах с реальными атрибутами/сообщениями; системная смена режима; нативный toolbar popup вручную. Отдельно проверить живой ТС с пользовательским выбором темы.
- Визуально: обычный попап, fallback, подтверждение копирования, раскрытый select, наведение и клавиатурный фокус. Контраст обычного текста — минимум 4.5:1; значимых границ/фокуса — 3:1. Проверить самый длинный хост и оба ряда копирования.
- Регрессии: `node tests/audit-ui.cjs`, `node tests/audit-background.cjs`, `python tests/audit-build.py`; затронутые браузерные проверки — по `tests/README.md`. Проверить наличие CSS и отсутствие новых разрешений в обоих ZIP.
- После реализации обновить architecture, status, tests/README, README и CHANGELOG; исправить утверждение AGENTS.md о единственной функции content script. Версию выпуска выбирать отдельно.

Критерий готовности: попап воспроизводит восемь локальных палитр, учитывает три независимые настройки, следует активной TS/gg-вкладке или системе по указанным правилам, корректно переживает недоступность темы и сохраняет переключение, копирование, preferred и fallback.
